## Corrections implemented

### Buffer barriers must match the scope of tracked state

`Buffer` keeps one access/stage state for a whole backing buffer. Its previous barrier covered only the suffix starting at the requested offset. Writing region A, reading a later disjoint region B, then reading A could therefore discard A's write history without making A visible.

The correction emits a whole-buffer barrier before replacing that whole-buffer state. It also retains dependencies for repeated writes, including explicit storage and host write flags. Identical read-only accesses still avoid redundant barriers. The small production helper is shared with a standalone C++ regression executable; the test does not duplicate the barrier implementation.

Six compiled regressions pass with assertions enabled and with `NDEBUG`. The upstream source copy also passes. Reintroducing the original suffix behavior makes the regression fail at `dependency covers A and B`.

This is conservative synchronization. It can increase memory synchronization costs for large shared backing buffers. An optimized successor would track intervals and preserve untouched intervals; dropping dependencies based on Dreams shader hashes would not establish correctness. The [Vulkan synchronization specification](https://docs.vulkan.org/spec/latest/chapters/synchronization.html) defines buffer-barrier memory scopes by the specified byte range.

### DS_SWIZZLE quad permutations need uniform quad-broadcast indices

The old frontend supplied a lane-dependent source index to `OpGroupNonUniformQuadBroadcast`. That operation requires a dynamically uniform index (and a constant index for earlier SPIR-V versions).

The correction emits only the distinct constant-index quad broadcasts required by the instruction pattern, then selects the appropriate result locally. There are at most four broadcasts. This preserves quad operations and their fragment/helper behavior. The research branch retains its existing inactive-source zero handling; the official-source patch deliberately preserves upstream's existing source-validity behavior and changes only index uniformity.

The structural regression exposed nonconstant indices before the change. On clean official source, the original implementation fails all 256 quad selector patterns; the corrected implementation passes all 256. On the research branch, fifteen GPU cases also pass: five patterns across three EXEC masks and 32 lanes. Those masks cover fully active, sparse, and endpoint-only lanes. These are instruction tests, not a Dreams playability test.

Shader binary cache versions were advanced: research branch 20→21, official-source patch 4→5. See the [SPIR-V specification](https://registry.khronos.org/SPIR-V/specs/unified1/SPIRV.html) and [AMD cross-lane instruction reference](https://gpuopen.com/learn/amd-gcn-assembly-cross-lane-operations/).
