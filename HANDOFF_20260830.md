## Validated facts

1. Compute shader `0x4ebeffd2` uses PS4 ordered-count semantics while creating the B1 seed stream.
   Allocating rows with one ordinary Vulkan atomic uses host workgroup-arrival order rather than the
   guest's logical token order and is nondeterministic.
2. The August 29 checkpoint implements collect, exclusive prefix in guest token order, replay, and
   final counter publication. One validated run used 64 logical groups, took the direct path with
   no fallback, and produced a fully covered and filled sculpt with normal floor/lighting and no
   observed jitter.
3. That image is progress, not final rendering correctness. The sculpt is still a grid of rounded
   panels instead of the intended Dreams fleck surface. A later empty-cache run of the preserved
   executable produced a complete but dark navy/black cube and the user observed jitter, so the
   visual result is not reproducible enough to call fixed.
4. The proven visible path is:

   `ordered sculpt records -> VS 0x3706083c -> FS 0xce3b8413 atlas coverage/depth -> VS 0xa33ab236 + FS 0xdcc325c2 decode -> lighting`

5. For one captured proxy pair, the original VS scalar math reproduced all captured clip positions
   bit-for-bit. Liverpool 16.8 raster coverage matched the covered and uncovered pixels, and the
   CE3 trace showed coherent atlas sampling, hit/miss, depth, and output. That evidence does not
   justify a VS, raster, CE3, or DCC patch for the missing-record problem.
6. The controlled scene stamped these eleven primitives in order: cube, cylinder, sphere, cone,
   donut, filled donut, triangular prism, hexagonal prism, tetrahedron, smooth cube, and curve.
   Producer `0x2bfebd3c` received only eight records, at x=`0,1,3,6,7,8,9,10`. Sphere and both
   donuts were already absent. Sphere target row 63 existed but was not referenced; donut row 66
   was zero. The missing shapes are therefore lost before VS, CE3, DCC, and lighting.
7. Surviving primitive replay payloads are distinct. The malformed results are not explained by
   one universal cube payload being replayed for every shape.

## Current hypotheses, separated from facts

- Highest-probability shared fault: an ordered compaction or publication edge drops, misorders, or
  fails to publish three of eleven records before `0x2bfebd3c`.
- Competing explanation: the CPU publishes only eight eligible scene/header records, and the GPU
  faithfully consumes an already incomplete prefix.
- A generic buffer-coherence risk exists in the later range-limited barrier work: one global access
  state is stored per backing `VkBuffer`, while barriers can cover only the current descriptor range.
  An intervening disjoint access may therefore replace the source state needed by a later read.
  This is a plausible jitter/stale-transform risk, not a confirmed cause.
- The dark complete cube may be a separate downstream material, DCC, or lighting defect. It should
  not be conflated with the upstream missing-record problem.
